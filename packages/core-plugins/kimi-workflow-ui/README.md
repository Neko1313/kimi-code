# Workflow UI

Optional presentation plugin for `kimi-workflow`. Install and enable both directories in `/plugins`, with `KIMI_CODE_EXPERIMENTAL_PLUGIN_RUNTIME=1`. Run `/workflows` or `/tasks`. The visualization opens in the editor slot through the same dialog host as `/model`. Background runs do not replace the editor until you open the dialog. Escape restores input while the workflow continues.

The view uses `Box`, `Text`, `Select`, `Button`, typed session state and the backend's `workflow` noun. It contains no engine imports or host-specific browser widget. [Adapter coverage and plan](../../node-sdk/PLUGIN_MODS.md) describes compatibility boundaries.

Enter on an agent requests its native transcript through `$.ui.view` in fullscreen mode. It shows user messages, thinking, assistant responses and tool results; Ctrl-O expands details and Escape returns to the workflow dialog. The task view stops its selected native task. Token targets and reported spend appear in the run header. View state and transcript requests are isolated by client.

Disabling this plugin removes the task presentation override. The backend continues to run independently.

Check the shared view against declarations generated by Claude's `/plugin-types`:

```sh
pnpm --filter @kimi-code-plugins/workflow-ui compat:claude /absolute/path/to/claude-code/index.d.ts
```

The view passes against 2.1.311. The registration module is the Kimi-specific bridge for the additional task render site; this check does not execute the plugin in Claude.
