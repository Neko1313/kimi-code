# Claude Mods adapter

The experimental `runtime.api: "claude-mods"` profile lets Kimi execute a supported subset of Claude Mods source. It is an independent implementation of the public API, not a copy of Claude's runtime. It does not promise compatibility with every Claude plugin.

## Contract and adaptation plan

The source audit follows the [announcement](https://claude.com/resources/articles/claude-code-mods), [first-mod tutorial](https://claude.dev/blog/getting-started-with-claude-code-mods/), [events guide](https://code.claude.com/docs/en/plugins/mods/events), [API guide](https://code.claude.com/docs/en/plugins/mods/api), [UI guide](https://code.claude.com/docs/en/plugins/mods/interface), [gallery](https://code.claude.com/docs/en/plugins/mods/gallery), and [managed-mod policy guide](https://code.claude.com/docs/en/plugins/mods/admin). The [original RFC](https://github.com/anthropics/claude-code/issues/91870) and its [architecture PDF](https://github.com/user-attachments/files/31802150/EXTERNAL.Function.Hooks.Core.Architecture.pdf) explain the early design; the current declarations define the detailed contract. These sources differ across versions, including older descriptions of isolation. Kimi modules execute as trusted Node.js code.

The compatibility fixture pins [upstream commit 26382c0](https://github.com/anthropics/claude-code/tree/26382c08758260c9f5deb2019d8fe851f89fa9ae/mods/agents-md). The [reference](https://code.claude.com/docs/en/plugins/mods/reference) recommends declarations generated by the installed Claude build over GitHub's copy. Neither matching types nor a passing fixture implies full runtime parity.

| Layer | Adaptation | Current coverage |
| --- | --- | --- |
| Loading | Recognize native and original mod packaging, compile TS/TSX and erase type imports | `api: "claude-mods"` or `.claude-plugin/plugin.json` plus `hooks/hooks.json.modules`; `h`/`Fragment` and `atom/read/update` from `claude-code`; JSX with the surface's kit; validated manifest options |
| Events | Preserve flat immutable input and onion delegation | Per-session `register(on, options)` closures, recursive object/regex/array matchers, `*` patterns, rewritten `next(e)`; repeated normal `next` calls; replay-safe `.catch` |
| Execution | Separate hook time from host work and preserve call provenance | Own-time budgets, cancellation, immutable `next.origin`, re-entry guards and `next.error.cause` |
| Custom API | Fold noun providers, dispatch each method through hooks | `engine.create`, two-level nouns, declaration merging; provider handlers sit beneath consumers |
| Storage | Keep JSON persistence separate from reactive session state | `store.get/set/delete/keys`; state get/set, snapshots, versions, CAS, owner checks, render-write refusal; frozen atoms, defaults and shape tags; CAS conflicts refresh the read snapshot for retries; state survives reload |
| UI | Keep element construction in plugins and placement in the host | `ui.resolve/open/close/panes/invalidate/log/view/status/toast`; Box, Text, Button, Select, single-line Input, plain Code/Markdown/Link text, SVG graphic views; native agent transcripts in the fullscreen TUI |
| Tools | Use the native registry, validation and permission pipeline | `tool.register/list/call/check`; session-scoped dynamic registrations; `tool.describe`, `tool.check` and onion `tool.call` hooks |
| Agents | Use the session's subagent and background-task services | `agent.spawn/list/stop`; explicit models; Kimi's `agent.run` extension for awaited results, usage and validated `StructuredOutput` |
| Prompts | Transform the request actually sent to the provider | `prompt.compose`, `prompt.section`, `prompt.context`; structured instruction files synchronized with `claudeMd`; caching until context reset, profile change, reload or invalidation |
| Instruction discovery | Use the active environment's filesystem and native Read checks | `fs.ancestors`, `session.root/cwd`, `env.get`; bounded Markdown imports, symlink permission checks and nested-file provenance |
| Interactions | Keep closures in the plugin; carry opaque handles over RPC | Pane/client/owner/key identity, stable handles across redraws, rejection after unmount/unload, Select value checks |
| Composition | Add host render sites without changing built-in task logic | Pane and the Kimi-specific `KimiTasks` site through `session.plugins.openSite()`; absent/failed providers preserve the built-in task browser |
| Workflow | Separate execution from presentation | `kimi-workflow` owns execution/journal and the `workflow` noun; `kimi-workflow-ui` owns `/workflows`, state, controls and task replacement |

Kimi-specific awaited agent results, isolated scripts, atomic store updates, task services and client context are available under `$.kimi`. Portable view modules consume custom noun contracts and standard UI/state APIs instead of importing the engine. `agent.spawn` returns `{ agentId, model }` while the native task runs, with `id` retained as a Kimi alias; `agent.run` is an awaited Kimi extension. Models must be explicit in Kimi even where Claude permits omission.

Mods can import `atom`, `read` and `update` from `claude-code`. SDK consumers can import the same helpers from `@moonshot-ai/kimi-code-sdk/plugin` or the SDK root. An atom is a frozen state address and default value; reading an absent value returns the default without writing it. `read` and `update` also accept plain state references. `update` applies a synchronous reducer and retries a version-checked write on contention. A conflict refreshes the dispatch snapshot before retrying; rendering remains read-only and only the owning plugin may write. An atom with `{ shape: 'v2' }` reads another stored shape as absent and writes `{ shape: 'v2', value }` on update. Loading these helpers alone does not imply UI or lifecycle compatibility with a mod.

Runtime manifests can publish native model tools through `runtime.tools`, an array of `{ name, description, method, inputSchema, isDeferred? }`, with the `tools` capability. `method` names a plugin-local domain method such as `workflow.run`. Dynamic `tool.register` tools are scoped to a session and use `mcp__plugin-id__name` as their model name. The engine validates input and preserves `Plugin(plugin-id.domain.method)` approval rules. Tools are removed on unload and never replace a tool belonging to another provider. Profiles must allow `Plugin` to activate these contributions. `tool.check` and `tool.call` cannot override engine deny rules or promote an approval request to an automatic approval; rewritten calls return through the native permission pipeline.

The `tools`, `agent`, `prompt`, `fs`, `session` and `env` capabilities gate their respective service namespaces. `tool.describe` changes the model-facing description and deferred flag; `prompt.compose` returns ordered sections, with shared sections before session sections. `agent.spawn` now wraps the native session spawn service, including built-in Agent calls and forks. Prompt, model and type rewrites return through native spawn planning; unchanged plans retain their model source and thinking settings. Agent identity, parent, fork mode and tool-call identity cannot be rewritten. Background, cwd and description rewrites are refused. Resume is a separate, unsupported contract.

At the Mods boundary, `Read.file_path/offset/limit` map to Kimi's `path/line_offset/n_lines`; the native tool schema stays intact. Each retry returns through native validation, permission checks and scheduling. Only the final tool result is published to the transcript. A mod can withhold a result after execution, which cannot undo the action. Returned `tool.call.context` strings become native context injections after the tool result, respecting tool-batch ordering.

The workflow plugin publishes `Workflow` this way; its workers use the current session harness. Legacy process-plan and pending-file entry points have been removed.

## Authoring

Point a plugin's TypeScript `paths["claude-code"]` at the SDK's `plugin` declarations when checking it for Kimi. Imports used only as types disappear at load. Runtime imports currently support `h` and `Fragment`; other imports fail compilation explicitly. A standalone UI component should accept the kit from `$.ui.resolve(e)` and plain data, as Claude's built-in diff views do.

```json
{
  "runtime": {
    "api": "claude-mods",
    "modules": ["./runtime/index.ts"],
    "capabilities": ["events", "ui", "state", "command"]
  }
}
```

`ui.render` receives `{surface, component, requestId, viewport, props}`. `Box` and `Text` produce `{type, props, children}`. A Select uses unique `options[].value` and `onSelect(value, event)`; an Input uses `onInput` and `onSubmit`. Each interactive element needs a unique string `key` within its site.

The CLI displays plugin panes in the editor replacement slot, through the same dialog host as `/model`. `/workflows`, `/tasks` overrides and `/panes` open the visualization without changing the transcript's width. Escape restores the editor; Tab/Shift-Tab move between controls, arrows navigate, Enter activates, and PgUp/PgDn scroll long output. Pane registration from a background run does not take focus. In fullscreen mode, a UI callback can request `ui.view({agentId})` to show the native transcript with user messages, thinking, responses and tool results; Ctrl-O expands details and Escape returns to the plugin dialog. View requests are isolated by client. Inline hosts display a fullscreen-mode notice.

Workflow runs are native background tasks linked to the initiating tool call. Their final result uses the existing task notification path; worker tasks retain their own transcripts without duplicate completion notifications. Schema-constrained workers submit `StructuredOutput`, retrying invalid responses in the same agent, with at most five validation failures. A contradictory closed-object schema is rejected before spawning.

Workflow journals append changed records and read older snapshot data. Optional `tokenBudget` accounts shared output-token usage, caps requests and stops exhausted runs; asynchronous provider reporting means in-flight requests may exceed the target. Missing output-token usage fails explicitly. `prefixStaggerMs` waits for the first shared-prefix worker's initial response, bounded by 5000 ms by default; 0 disables the wait. Cache support and cache hits still depend on the provider. The isolated script host wakes on work completion rather than polling an idle interpreter.

`ui.open` dimensions are hints. Explicit noninteractive hosts return `{isPlaced:false}`. Session state is shared across clients unless a plugin uses a family member keyed by `props.viewId`; Kimi provides this client identity on pane render events. Closing a viewer does not cancel workflow execution.

## Failures, budgets and origins

`on(...).catch(handler)` attaches one recovery handler to that registration, before `register` finishes. A second attachment, a late attachment, and a catch on `engine.create` are refused. Throwing or returning an invalid supported event result invokes the catch. Without a recovery result, the failed link is skipped: a continuation that already ran is reused; otherwise the original event continues once. A catch that throws, times out or returns `undefined` uses the same fallback. The workflow provider catches its own failures and returns an explicit denial, preserving actionable validation errors.

```ts
on('tool.call', { tool: 'Read' }, async ($, e, next) => {
  return next(e)
}).catch(async ($, e, next) => {
  if (next.called) return next(e)
  return { deny: 'Read guard failed: ' + next.error.kind }
})
```

`next.error` is frozen data with `kind` (`throw`, `timeout` or `re-entry`), an optional message and the catch grace in `budget`. `next.called` records whether the original hook started a continuation. Recovery waits for the latest continuation to settle; every recovery `next` then reuses it, ignoring the argument. If none ran, the first recovery `next` starts one, and later calls reuse it. Ordinary hooks may deliberately call `next` again, including tool retries.

An ordinary Mods hook gets 10,000 ms of its own elapsed time; recovery gets a fresh 1,000 ms. `next.budget` reports `{ ms, remainingMs }`. Time while any host API or `next` call is in flight is excluded, including overlapping calls; clock delays count as the mod's own wait. `engine.create` has no hook budget. Native Kimi handlers keep their existing 30-second wall-clock bound. Mods commands and custom methods do not acquire that additional outer wall-clock timeout.

An expired hook's `next.signal` aborts and its stale continuations and host API calls are refused. An event interrupted by its caller, a closed agent or an unloaded plugin is cancelled rather than recovered into new work. A hook still running 5,000 ms after abandonment is logged. These are cooperative bounds in trusted Node.js: a synchronous infinite loop cannot be preempted by an in-thread timer. Elapsed time is checked again when control returns. Timers registered with `$.clock` and declared `$.kimi.tasks.start` jobs run outside the original hook's frame; jobs retain their own cancellation signal.

`next.origin` is a frozen `{ plugin, tier }` set by the host outside event data. Native engine events read `{ plugin: 'engine', tier: 'core' }`; API calls and timer callbacks identify their plugin with tier `user`. All hooks of a dispatch see the same origin even if a preceding hook rewrites fields named `origin` or `provider`. Subagents started by a plugin raise their subsequent model/tool events as the engine.

A mod's API calls skip its own hooks, and an already active hook cannot enter again through another plugin. Its catch may handle `kind: 're-entry'`; `cause` is `rewritten` for tool/spawn rewrites or `lent` for a cycle through another plugin's custom namespace. Recovery itself is guarded so a recovery API call cannot recurse into the same catch. Independent concurrent dispatches keep separate ancestry.

## Boundaries and next compatibility steps

Persistent `AbovePrompt` hooks now compose across enabled mods and render above the editor in both regular and fullscreen terminals. `ui.status` and expiring `ui.toast` messages render there too. `Ctrl+Shift+B` focuses plugin controls; `Tab` moves between controls, `Enter` activates one and `Esc` returns to the editor. Keyboard focus reveals `hover: { display: 'flex' }` controls; permanently hidden and disabled controls are excluded from navigation. This is a keyboard fallback, not mouse hover or general CSS support. SDK hosts render sites through `session.plugins.renderSite()` and route controls through `dispatchSiteKey()`; pane APIs keep their existing behavior. Callback handles remain scoped to the plugin, site and client. Explicit headless hosts render no persistent UI and refuse site actions.

The TUI dispatches `ui.render` for `Spinner` and the Kimi-specific `ContextUsage` site in their native locations. A hook can return a tree or wrap the result of `next(e)`; an unchanged result retains the native component. `Spinner` exposes `word`, `message`, `suffix`, and `mode`; `ContextUsage` exposes `text`, `tokens`, `window`, and `percent`. Both sites currently render a single line, and controls at these sites do not receive keyboard focus. Sites for messages and tools are not yet connected.

A `ContextUsage` hook can return an empty `Text` element to hide the native counter when a mod draws that information elsewhere. Unloading the mod restores the built-in counter.

SVG graphic views are an additional opt-in: enable both `KIMI_CODE_EXPERIMENTAL_PLUGIN_RUNTIME=1` and `KIMI_CODE_EXPERIMENTAL_PLUGIN_GRAPHICS=1`. The TUI requests `surface: 'desktop'` only in this mode and only when a local Chrome/Chromium renderer is available. SDK `renderSite`, `openSite` and `renderPane` accept an optional `surface`; their default stays `terminal`, so existing SDK callers and terminal-only plugins keep the old path. Owned callbacks carry the surface on which they were drawn. `session.surfaces()` reports recently active UI clients, with the existing terminal fallback when none has rendered.

`$.ui.resolve(e).Svg({source, alt, width?, height?})` accepts SVG markup up to 1,000,000 characters; `alt` is required and dimensions are CSS pixels. The graphical host handles SVG CSS/SMIL animations, flex layout, absolute overlays and viewport clipping. Timelines survive unrelated widget updates. Frames advance locally with a 20 FPS target and backpressure; animation does not dispatch engine hooks or RPCs for every frame. Frame dimensions are bounded to 240 columns, 32 rows and 2 million pixels, with further row clipping when necessary. Page keys scroll graphic panes; keyboard focus reveals controls without mouse support.

The renderer uses an installed Chrome or Chromium through a private DevTools pipe and a temporary profile; it never opens the user's browser profile. Browser sandboxing remains enabled, remote resource requests are blocked and SVG scripts, event attributes and embedded active documents are stripped. Missing or failed browsers produce a notice and restore the text path; malformed SVG leaves display their alt text without disabling other drawings. Set `KIMI_CODE_PLUGIN_GRAPHICS_BROWSER` to an absolute executable path when detection cannot find the browser. `KIMI_CODE_PLUGIN_GRAPHICS=cells` forces colored quadrant-cell output; otherwise Kitty/iTerm2 images are used when supported. In cell mode HTML text and SVG labels remain terminal characters, while graphics use colored cells. Set `KIMI_CODE_PLUGIN_GRAPHICS=off` or disable the graphics flag to keep text-only rendering. `canvasBackground` in custom themes controls the drawing background. Hidden views stop producing frames, closing a view releases its page, and the browser exits five seconds after the final view closes or the TUI closes.

`KIMI_CODE_PLUGIN_GRAPHICS=sextants` selects a denser cell renderer, even in terminals that support images. It chooses either a 2×2 quadrant or a 2×3 sextant for each cell by comparing their reconstruction error. It needs a terminal font or fallback font that covers Unicode U+1FB00–U+1FB3B with single-column glyphs; otherwise use `cells` or an image-capable terminal. The default `auto` mode is unchanged.

`KIMI_CODE_PLUGIN_GRAPHICS=octants` also considers 2×4 blocks, using Unicode U+1CD00–U+1CDE5 and existing block characters. This experimental mode requires both a font with those glyphs and a terminal that handles them as single-column characters. A font alone does not guarantee terminal support; use `sextants`, `cells`, or the default image protocol when octants are missing or misaligned. JetBrains JediTerm and VTE-based terminals fall back to sextants with a notice because they may render octants as missing-glyph boxes. If you have verified that your terminal and font display octants correctly, use `octants-force` to bypass this fallback.

The Kimi-specific `kimi.ui.rendered` hook runs after the `ui.render` chain for a render site. It receives the composed `tree` and can return a modified tree while preserving the other plugins' callback handles. The optional `kimi-atelier-footer` plugin uses this hook to move Atelier's quota display into `ContextUsage`, keeping Atelier's other controls intact. It restores the native footer when Atelier's band is hidden or its context usage is unavailable.

`session.id/model/version/surfaces/usage` are available through the Mods adapter. Usage reads the native context counter and model capacity; managed Kimi account windows come from the authenticated usage API and are cached for 30 seconds, including concurrent readers. Kimi exposes `five_hour`, `seven_day`, `monthly` and `monthly_code` only when the account returns them. Missing account windows, monetary costs and detailed context breakdowns are not fabricated. In text mode, the original Clawd mod draws its block mascot and emoji; the graphics mode selects its original animated SVG scenes; Atelier supplies the context/limit band. Mods can ignore window kinds they do not recognize. Git/Android functionality still requires APIs outside this implemented slice.

With the runtime flag enabled, a configured model and an enabled UI plugin, the TUI creates an empty session before the first message so its widgets can initialize. It does not start a model turn. With no enabled UI plugin, ordinary lazy session creation is preserved.

This profile covers the workflow UI and the tested `agents-md` path, not the complete upstream API. Kimi's legacy hook events retain Kimi payloads; `session.start`, `turn.start`, `turn.complete`, `session.measure` and model-switch notifications are bridged to native session events. Store, state, UI placement, command registration, clock reads, instruction discovery, session paths, environment reads and custom noun calls go through middleware. Timer callbacks and synchronous UI helpers retain native semantics. `ui.log` currently writes to the debug log; explicit transcript targeting is refused.

Not implemented: Claude model/config/settings/audio/MCP services, agent definitions and resume APIs, stream generators, managed tier routing (`next.to`, `plugin.register`), trace histories, `derive/memberOf` state helpers, Client/Raster/Image, mouse interactions, general CSS/hover layout, multiline input, rich Markdown/code highlighting, replacement sites for spinner/message/tool rows. Installed plugins cannot claim a managed or built-in tier. Classic hooks in Claude's `hooks/hooks.json` are not translated. Native state lifetime differs from Claude's reset-on-clear/resume/branch behavior; no `classic.SessionStart` reset adapter exists. Unsupported namespaces and methods report an error; unsupported layout props are not a compatibility guarantee. The shared `runtime/view.ts` typechecks against both Kimi SDK declarations and Claude Code 2.1.311 declarations. The small Kimi registration module owns the additional task render site. No execution inside the proprietary Claude host has been performed.

## Running the original agents-md

Install a local copy of the original `mods/agents-md` directory through `/plugins`, enable it, and enable the experimental runtime with `KIMI_CODE_EXPERIMENTAL_PLUGIN_RUNTIME=1`. No Kimi manifest or source edits are needed. Native Kimi manifests take precedence when both formats exist. Original mod manifests do not declare Kimi capabilities, so the adapter grants the supported host namespaces under the same trusted-code model.

Manifest `userConfig` defaults are passed to `register`; overrides live in Kimi's configuration:

```toml
[plugin_runtime.options."agents-md"]
instructionFiles = "claude-md-and-agents-md"
```

The original four `instructionFiles` modes are accepted and validated. Kimi's existing `AGENTS.md` loader remains active; the original mod deduplicates those files and adds missing ones, including `.claude/AGENTS.md`. `claude-md` leaves the native instruction set untouched; it does not make Kimi acquire Claude's loader. `managed-only` filters the structured initial instruction set; it is not an organization-policy or sandbox guarantee, and does not redact previous conversation messages or replace Kimi's other context sources.

Run the reproducible compatibility check from the checkout:

```sh
pnpm --filter @moonshot-ai/agent-core-v2 compat:agents-md
```

The check downloads 75 original files at the pinned commit into ignored `.tmp`, verifies Git blob hashes before and after execution, and runs the unmodified entry point through Kimi. It checks modes, native-file deduplication, Markdown imports, attachment switches, per-session closure isolation, once-per-agent nested instructions and fork inheritance. A native harness case runs through both memory and IPC: it captures provider requests, checks denied imports, executes real `Read` calls, forks, clears and compacts context, and reloads option overrides. The provider is deterministic; no external model or credentials are used. Anthropic's own `claude-code/testing` suites are not executed by this check. The ordinary test command skips fixture-dependent cases unless `CLAUDE_MOD_FIXTURE` is set.

## Priorities from the contract audit

| Priority | Contract | Kimi action and acceptance criterion |
| --- | --- | --- |
| P0, implemented in this change | Immutable events, instruction provenance, retries and actual spawn interception | Preserve copies between handlers; synchronize files/text at each link; recheck permissions per attempt; observe forks at the native lifecycle boundary. Original `agents-md` must run unchanged. |
| P1, implemented | Failure policy and hook budget | Registration `.catch`, called/error metadata, continuation replay and 10,000/1,000 ms own-time budgets. Tests cover errors, invalid results, timeouts before/after delegation, overlapping host waits, cancellation and stale work. |
| P1, implemented | Origin and re-entry | Out-of-band frozen origin, guarded self/cross-plugin calls and rewritten/lent recovery metadata. Native memory/IPC tests verify plugin spawn origin, engine child-tool origin, no duplicate execution after catch and preserved deny rules. |
| P1 | Managed order | Add tier-aware dispatch, `next.to` and `plugin.register` before claiming compatibility with `sec-default`. Installed plugins currently occupy only the user tier. |
| P1 | Session lifecycle and state | Define reset/reload/restore behavior for state and module instances, expose `classic.SessionStart` where appropriate, and gate new background work after a user interruption. Test two clients, two sessions and resumed sessions. |
| P2 | General render sites and engine references | Add stable `{ type: 'engine', ref }` nodes so plugins can wrap native rows without rebuilding them. Extend the existing site mechanism to task rows, messages and spinner; preserve fallback, keyboard focus, scrolling and native accessibility. Keep the requested `/model`-style workflow placement. |
| P2 | Portable SDK helpers and streaming | Implement versioned fixtures for atom/read/update and async-generator events; then extend the element kit and input events. Expand namespaces only through native services. |

These priorities follow observable differences from the public contract, not a claim about Claude's proprietary implementation. The RFC's uniform event/API design is useful for keeping features in plugins; it does not require Kimi to adopt every Claude default or rendering placement.

Expansion order: add a contract fixture for each new method/event; expose its Kimi engine operation behind existing permissions; extend the SDK/wire and terminal renderer where needed; then test shared component source against both declaration sets. Do not implement workflow-specific widgets in the host. Further render sites should use the same `openSite` and element/callback path.

Runtime modules remain trusted Node.js code. Capabilities gate the host API, not Node imports. Only generated workflow scripts run in the isolated QuickJS interpreter. Missing custom providers fail when called. The UX plugin requires the workflow backend to be installed and enabled.
